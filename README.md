# Digital Passport

Сайт использует макет `digital-passport-roles-mvp.html` как точную визуальную основу. Frontend запускается на React/Vite, backend — Spring Boot 4.1.1 и PostgreSQL 18.

Двухминутный сценарий показа техзаказчику: [DEMO_GUIDE_2_MIN.md](DEMO_GUIDE_2_MIN.md).

## Запуск

1. Убедитесь, что PostgreSQL работает на `localhost:5432`, база и пользователь `postgres`, пароль `postgres`.
2. Запустите backend: `cd backend; .\mvnw.cmd spring-boot:run` (нужна Java 21).
3. Запустите frontend: `cd frontend; npm install; npm run dev`.
4. Откройте `http://localhost:5173/`. Для демонстрационных ролей ТХЗ и завода пароль `demo123`.

Первый вход ТХЗ добавляет три демонстрационных проекта в БД. Кнопка «Создать проект» создаёт новый проект. Импорт IFC4 принимает файлы до 100 МБ, включая `Telegraf_bez_arm.ifc`: извлекаются колонны, балки, плиты, стены и фундаменты, GlobalId, ExpressID, название и этаж. Пользователь выбирает элементы для отдельных паспортов. Модель сохраняется в БД как версия; повторный импорт сопоставляет элементы по GlobalId.

В проекте «Телеграф · образец IFC» уже сохранены три колонны из образца. Обзор проекта показывает всю загруженную IFC-модель: клик выделяет элемент, двойной клик изолирует его или возвращает модель. Справа есть список всех элементов IFC с поиском, фильтром по типу и страницами; выбор строки изолирует элемент. Можно скрыть и показать модель, открыть её на весь экран. В паспорте отображается отдельная геометрия конструкции. В 3D-окне доступны вращение, масштаб, панорамирование, подгонка вида и каркас.

Документы PDF/JPG/PNG до 10 МБ сохраняются в PostgreSQL и доступны по ссылкам из карточек. QR создаётся в паспорте, показывается на сайте и ведёт на постоянный URL, требующий входа. Кнопка поиска по QR распознаёт код на фотографии. Реестр конструкций, контроль исполнения, приёмка качества и списки IFC имеют поиск, фильтры и пагинацию. В окнах заказа, импорта и отгрузки можно выбрать все отфильтрованные элементы, в том числе на других страницах. Из модели проекта и каждой строки приёмки можно открыть паспорт элемента. Завод может подтвердить изготовление всей зарегистрированной партии одним действием; для каждого изделия сохраняется отдельное событие. Изменения проектов и события интерфейса сохраняются в PostgreSQL; сервер проверяет организацию, роль и ряд защищённых полей.

Проверка: `cd backend; .\mvnw.cmd test`, `cd frontend; npm run build; node scripts/batch-manufacture-smoke.mjs; node scripts/list-fixes-smoke.mjs; node scripts/project-smoke.mjs; node scripts/qr-smoke.mjs; node scripts/workflow-smoke.mjs` (для браузерной проверки нужен установленный Microsoft Edge и запущенные серверы).

## Ограничения текущей реализации

Интерфейс сценариев основан на исходном HTML-макете внутри React-оболочки. Операции заказа, производства, получения и приёмки сохраняют состояние проекта, но ещё не вынесены в отдельные серверные транзакции со всеми проверками переходов и конкурирующих изменений из ТЗ. Для паспортов импортируются колонны, балки, плиты, стены и фундаменты. Общий обзор дополнительно показывает арматуру, проёмы, двери, окна, крыши, лестничные марши и ограждения. Элементы IFC без 3D-представления остаются в списке; извлечение свойств материалов ещё не реализовано. Для чтения QR используется фотография из файла или камеры телефона через поле загрузки.
